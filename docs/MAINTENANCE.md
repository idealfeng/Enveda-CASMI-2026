# 项目维护与清理规则

## 固定入口

以 [项目导航](../PROJECT_INDEX.md) 为入口。提升账本是正式最佳分的唯一来源；逐日experience保留细节，LESSONS保存已修正结论，模型注册表保存实际文件指纹。历史原件保持原路径。

## 每轮实验结束做什么

1. 按 [模板](EXPERIMENT_TEMPLATE.md) 记录对照、真实改动、产物、结果和决策，包括失败。
2. 更新 [路线索引](EXPERIMENTS.md)；新的负证据或被推翻结论更新 [LESSONS](LESSONS.md)。
3. 在项目根目录运行：`.venv\Scripts\python.exe scripts/refresh_project_index.py`，再执行同命令加 `--check`。它只读取本地文件，不执行权重、不联网。结果表是当时快照，查最新分看活动watcher。
4. 新增严格高于最佳的正式COMPLETE、无error分数时，更新提升账本并注明父版本、来源和归因边界。当前固定批次已有自动记账工具，不并行手工写同一账本。

## 存放与保留

| 类型 | 放置位置 | 保留方式 |
| --- | --- | --- |
| 数据/公开权重 | assets内来源/版本目录 | 保留来源、版本和SHA；不按模型文件名随意覆盖 |
| 自训练权重/训练缓存 | runs内实验目录 | 保存配置、seed、步数、报告；500步中间权重与2500步部署权重分别标注 |
| 正式提交 | submission内批次目录 | 源码、metadata、recipe、manifest冻结，不迁移或原地修补 |
| 结果/核验/故障材料 | reports内批次目录 | 结果、日志、审计和提交编号保留；新结论补链接，不抹掉旧错误 |
| 用户原始实验 | produre1、produre2 | 保留原件；独立复核另写reports |
| 安装缓存 | .cache | 仅确认闲置后按明确清单清理；保留离线wheels及证书 |

## 不能按目录大小直接去重

`reports/shared_asset_links.json`等记录了已验证硬链接。多个路径可能共用一份磁盘内容，目录汇总会重复计数。模型注册表按SHA列出相同权重，但同SHA不代表两个路径都可删：旧manifest、Notebook及本地脚本可能依赖它们。

`runs/`下也有历史验证产物、真实canary、共享谱缓存和部署权重。删除大型临时数组前，先核查引用、可重建来源和对应报告，不整目录批量清空。实验暂时不采用时用状态标记，避免搬目录破坏既有引用。
