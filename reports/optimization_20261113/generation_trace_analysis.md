# 11/13 generation 实际机制与后续名额建议

当前只推荐这一个已修复的正式候选，等待真实隐藏评分。不再盲加第二个生成配方；本报告只解析已保存的实际 trace，没有重新运行模型，也没有重做 produre1/2。

## 确认增加了什么

冠军原本已经启用生成：6 母体、总上限 150、每母体 60、双步，允许近零质量差的同分异构化。当前候选同时改变了母体数 6→12、总上限 150→300、同分异构化开→关。若榜分提升，只能先归因于这套生成改动整体；不能说成“首次加入 Class-3 生成”或单独归功于更多母体。

两条查询都真实访问了第 7–12 母体，合计至少 211/308 个接受候选来自这一扩展范围。原始产物数包含后续去重、身份排除和质量过滤前的产物，不能当作候选数。trace 未直接绑定每次调用的 rank 与 parent sid，因此不猜测晚母体接受数的更精确值。

实际特征矩阵是 252 列，原 ranker 从中严格选取 160 列并实际打分；矩阵、投影和得分都有哈希。两个 Engine top-25 中，分别有 8、7 个 raw-SMILES 与生成列表相交；最终 CSV 合计相交 14 个。这些是运行机制观察，不能当作新增真结构、Class-3 召回或排名收益，因为没有同次执行的原冠军对照。

关同分异构化的具体语义是：当母体与目标质量差接近零时，不枚举质量中性变换组合。非零质量差的双步反应仍保留，不能把它理解成关闭异构体排序或关闭所有双步。

## 为什么暂不加第二版

12 母体、150 上限、同分异构化保留，是一个较干净的“只增加母体数”对照，但原组件记录中两条查询都已触 150 上限，后 6 母体可能根本没有机会参与。它尚未显示新的候选或排序收益。12 母体、150 上限、关闭同分异构化可以与当前版作预算对照，但也只是裁切候选，当前没有独立收益证据。这里的两个已知答案查询只用于部署路径诊断，不能据其结果挑下一配方。

若当前真实榜分确有提升，优先考虑一个固定归因对照：**6 母体 / 总上限 150 / 每母体 60 / 双步 / 关闭同分异构化**。其对冠军只改变同分异构化，能帮助区分“剔除中性枚举”与“扩大生成预算”的贡献。这只是条件满足后的归因建议，今天不构建、不占正式额度。实现应从当前已验证源码派生新版本：CONFIG 与观察器的母体/总量边界必须共同改为 6/150，冻结新的 module/recipe/Notebook SHA，保留完整初始化和最终 CSV 审计；不能只改 CONFIG 而留下写死的 12/300。

输入含未消费的标签元数据，边界见 `generation_disclosure_addendum.md`。完整生产成功不等于准确率成功；本报告不提供新的效能指标。
